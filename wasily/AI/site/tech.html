浏览器 MCP 与训练数据闭环
架构设计与接口文档

本文描述 Wasily 能力总线中两个新增子系统：基于 CDP 的内置浏览器 MCP 服务，以及从会话采集到 SFT 数据集导出的训练数据闭环。文档同时给出标准接口定义、安全约束与实测报告。

版本 v1.0 协议 MCP 2024-11-05 更新 2026-11-19 测试 62 项通过 工具总数 111

1. 概览

两个子系统都挂在同一能力总线上，遵循相同约定：标准 MCP 工具、JSON 可序列化结果、失败时返回 ok:false 而不是抛出进程级异常。

浏览器 MCP

9 个工具，CDP 驱动，支持打开、导航、快照、点击、填写、截图与脚本执行。

训练闭环

8 个工具，采集 294 条历史交互，清洗为 242 条，导出 223/19 训练验证集。

第三方接入

HTTP JSON-RPC 网关，暴露 111 个工具；支持运行时注册 stdio / http 服务。

2. 浏览器 MCP 架构

协议层与驱动层严格分离。上层只认识 MCP 工具，下层只认识 CDP；替换浏览器内核时，工具定义与第三方调用方式保持不变。

2.1 会话生命周期

ensure_browser→ /json/new→ WebSocket 连接→ Page.navigate→ Runtime.evaluate→ 结果归一化
  • 自动拉起：browser.auto_launch=true 且 9222 无响应时，探测 Edge/Chrome 并以临时用户目录启动。
  • 标签页复用：进程内维护单一调试连接与目标页，后续命令复用，避免反复建连。
  • 关闭语义：browser_close 只断开调试连接，不强制结束用户浏览器进程。

3. 浏览器 MCP 接口

服务名 wasily-browser，命名空间 mcp__browser__，传输方式 stdio。

工具参数返回要点
browser_status无alive、driver、port、executable、connected、url
browser_openurl 必填url、title、target
browser_navigateurl 必填跳转后的 url 与 title
browser_snapshotmax_chars，默认 8000可见文本 text、title、truncated
browser_clickselector 或 textclicked、跳转后 url
browser_fillselector、valuelength；触发 input/change 事件
browser_screenshotpath 可选path、bytes，默认写入 outputs/browser
browser_evalscript 必填result；受 browser.allow_eval 控制
browser_close无断开连接，保留浏览器窗口

4. 训练数据闭环架构

闭环由四段组成：采集、清洗、标注、导出。所有中间产物均为 JSONL，可增量重跑，不依赖数据库。

sessions_store+ train_append→ events.jsonl→ 清洗/脱敏/去重→ dataset.jsonl
dataset.jsonl→ 标注→ labeled.jsonl→ 按哈希划分→ train.jsonl / val.jsonl+ manifest.json
feedback.jsonl← train_feedback← 用户评分

4.1 数据目录

文件内容
outputs/training/events.jsonl原始问答对，含 session_id、工具名、时间戳
outputs/training/dataset.jsonl清洗与脱敏后的样本
outputs/training/labeled.jsonl附加任务类型、成功标记、质量分
outputs/training/train.jsonl / val.jsonlSFT 格式：messages + meta
outputs/training/feedback.jsonl0–5 分评分与备注
outputs/training/manifest.json生成时间、样本数、划分比例、文件路径

4.2 自动采集

  • kb 服务启动时调用 start_auto_collect()，后台线程按 training.interval_sec 增量扫描会话目录。
  • 事件 id 由会话 id、消息序号与内容摘要生成，重复扫描不会重复入库。
  • 实时采集由 train_append 提供，上层可在每次对话完成后写入。

5. 训练闭环接口

工具参数返回要点

端点方法说明

/mcpPOSTJSON-RPC：initialize / tools/list / tools/call / ping
/v1/mcp/registerPOST注册第三方 stdio 或 http 服务并热重载

curl -X POST http://127.0.0.1:8000/v1/mcp/register \
  -H "Content-Type: application/json" \
  -d '{"name":"my-service","transport":"stdio",
       "command":"python","args":["server.py"]}'

当前网关聚合 8 个服务、111 个工具。内置服务名 self、kb、browser 受保护，不允许覆盖或移除。

7. 安全设计

网关鉴权

未配置 mcp.gateway_token 时仅回环地址可调用；配置后必须携带 Bearer 令牌。注册接口始终只允许本机。

浏览器隔离

自动拉起使用独立临时配置目录，不读取用户日常浏览器配置；allow_eval 可关闭脚本执行。

数据脱敏

清洗阶段替换 sk-*、Bearer、password、api_key、secret、token 等敏感串为 [REDACTED]。

最小权限

训练与浏览器服务均为独立 stdio 进程，只通过标准输入输出通信，不监听额外端口。

8.5 已知限制

  • 网关采用请求-响应式 JSON，未实现 SSE 流式传输；对需要服务端推送的客户端需后续补充。
  • 浏览器驱动当前仅实现 CDP；Firefox/WebKit 需新增驱动层实现。
  • 标注为启发式规则；train_label 预留了扩展位，尚未启用模型标注。
  • 反馈暂未自动参与质量重排，仅落盘留存。
