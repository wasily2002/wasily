Model Context Protocol
MCP：把外部能力接进同一个工具表

配置在 wasily/AI/mcp.json，支持 stdio 与 HTTP 两种传输。连接成功后每个 server 的工具自动以 mcp__<server>__ 前缀注册，与内置工具平级参与 tool_call 循环；只读工具直接执行，写类工具默认需要确认。

🎚Ask / Plan / Agent 三模式

请求体 mode = ask | plan | solo

Ask 纯问答、Plan 只给方案、Agent 自主执行。只读模式在服务端硬拦截写工具（不靠模型自觉），越权调用直接返回拒绝原因。

原理：模式随每次请求下发，工具白名单在调度层按 mode 过滤；ide_edit_file / ide_run_terminal 同样纳入拦截。
服务端硬拦截按请求下发

🗜上下文压缩 /compact

POST /v1/context/compact

把较早对话折叠成摘要块并落盘，保留最近若干轮，长任务不再撞上下文上限。输入框输入 /compact 即可触发。

原理：context_net.compact(sid, messages, keep) 生成折叠摘要，写回会话存储；返回压缩前后 token 统计。

🗂多窗口标签

windowId + 独立 sid

面板内每个标签是一个独立窗口：各自的会话、上下文、附件与任务状态互不覆盖，可以同时跑多个 Agent。

原理：IDE 上下文按 windowId 分存 ide_context.json；运行态按 session_id 拆分，并发请求互不阻塞。
独立会话并发

🧱内容渲染引擎

ide_panel.html

代码块带行号、超 20 行折叠、一键复制与语法高亮；终端块区分命令行与输出；文件树 / 文件预览卡片；提醒块与多步骤进度块；历史消息分段渲染，上滑增量补更早内容。

原理：流式 token 先入队、50ms 批量渲染避免重排；同一轮连续同类工具结果合并为分组卡片，不给每条都开新卡。

🔔任务完成通知

notifyTask → /notify_stream → /notify_click

任务完成、需要确认或出错时弹系统通知；窗口最小化也弹，点击通知回到对应窗口与会话。同类事件做合并限流，避免轰炸。

原理：扩展宿主向本地通知流注册客户端，服务端推送事件；点击经主进程恢复窗口后回传 /notify_click，按 sid 定位会话。

#️⃣上下文快捷添加

@ 与 / 与 #

输入 @ 选文件、/ 选命令与技能、# 精确加入 #Code #File #Folder #Workspace #Web #Past Chats；也可从资源管理器拖文件进对话框。

原理：选择器把路径/选区/网页内容转成结构化附件随消息发送，服务端统一拼进上下文，不靠模型猜。
