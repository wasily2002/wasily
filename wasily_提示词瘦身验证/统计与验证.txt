五、压缩手法（逐条可核查）
============================================================
1) 去掉重复表述：BASE_PROMPT 重写，删除与工具清单重复的「调用格式」块；
   get_tools_prompt 不再重复输出 tool_call 语法。
2) 长示例改短示例：orchestrator 复杂编排只留最小 JSON 示例；技能库只列「名称 + 前 3 个触发词」。
3) 规则短句化：读文件规范由长句压成分号条目；BASE_PROMPT 执行链路/执行风格压成 2-3 条。
4) 长说明移进工具 description：read_image / read_pdf / read_office / fetch_web /
   sequential_thinking / task_done / memory_save / file_read / code_read 的 description 精简，
   系统提示里只留「按类型选工具」的规则。
5) 记忆限长：memory_net 召回 top 5→3，且按简单/复杂分别截断 420/720 字符。
6) 历史摘要截短：单条 user 32 字、assistant 50 字，最多 3 条，标题加「历史不代表本轮已执行」。
7) 保留约束：只读拦截（READONLY_REJECT_MSG）、Ask/Plan 行为约束、动作型硬约束、
   tool_call 输出格式、数据非指令规则全部保留，未为瘦身删掉任何一条。
